# PR 템플릿 (한국어 / 내부 프로젝트용)

내부 팀 프로젝트, 사내 저장소 등 한국어로 소통하는 프로젝트에 사용한다.
아래 구조를 그대로 따르되, 내용이 없는 섹션(예: 스크린샷, 관련 이슈)은 통째로 생략한다 — 빈 섹션을 "없음"으로 채우지 않는다.

## 제목 형식

```
<type>: <한글 요약>
```

- `type`은 저장소의 커밋 컨벤션과 동일하게 맞춘다: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `style`, `perf` 등.
- 저장소에 이미 병합된 PR 제목 스타일이 있다면(`gh pr list --state merged`) 그 스타일을 우선한다.

## 본문 형식

```markdown
## 개요
<이 PR이 왜 필요한지, 무엇을 해결/추가하는지 1~3문장>

## 변경사항
- <변경점 1>
- <변경점 2>

## 테스트
- [ ] <검증 방법 1 — 실행한 명령어나 확인한 시나리오>
- [ ] <검증 방법 2>

## 스크린샷
<UI 변경이 있을 때만 포함>

## 관련 이슈
Closes #<이슈 번호>

## 리뷰 시 참고사항
<리뷰어가 특히 주의 깊게 봐야 할 부분, 설계상 트레이드오프 등. 없으면 섹션 자체를 생략>
```

## 작성 원칙

- 커밋 메시지·diff에서 실제로 확인한 내용만 쓴다. 코드를 보지 않고 추측한 내용은 쓰지 않는다.
- "왜"에 집중한다 — 무엇이 바뀌었는지는 diff가 보여주므로, 본문은 배경과 의도를 우선한다.
- 문체는 담백한 서술형("~함", "~추가", "~수정")을 쓰고 과도한 격식체는 피한다.
